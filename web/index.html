    LEARN THE WHOLE SYSTEM
    From an API response
    to an answer you can verify.
    The tools matter because each one solves a specific part of the problem.
    
    
    
      
    01
    Extract without rewriting history
    Python reads sandbox reporting pages. JSON keeps the original structure. Each distinct payload gets a SHA-256 fingerprint; repeated observations are tracked separately, so replay never creates another payment.
    raw_records + record_sightings
    
      
    02
    Make bad data visible
    Validate timestamps, event codes, statuses, and exact decimal amounts. Preserve rejected rows with a reason. Normalize dates to UTC and keep currencies separate. A later status update becomes another historical version.
    valid_records + quarantine
    
      
    03
    Resolve state with inspectable SQL
    DuckDB runs window functions over historical versions. dbt orders the dependent models. Conflicting latest values go into the ambiguity model instead of being chosen arbitrarily.
    conflicts → payments → daily_activity
    
      
    04
    Test before anyone sees the result
    Each run builds a separate warehouse. Tests check unique keys, excluded ambiguity, and agreement between details and summaries. Only a passing build replaces the published pointer. Readers can keep using the previous version during a refresh.
    candidate → dbt build → atomic publication
    
      
    05
    Serve evidence, then explain it
    FastAPI exposes bounded, parameterized queries. Parquet provides a typed columnar export. An optional cloud model receives aggregate evidence and a question. It cannot run SQL, alter records, or move money.
    SQL evidence → optional AI explanation → human review
